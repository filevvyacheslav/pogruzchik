# Лендинг

Сайт на HTML5, CSS и обычном JavaScript. Без Node.js, сторонних JavaScript-библиотек и сборки. Файлы можно загрузить на PHP-хостинг.

## Публикация

Проект подготовлен для публичного репозитория GitHub и GitHub Pages. Основная ветка — `main`. Сборка не требуется.
Публикация выполняется только по явному запросу пользователя. Workflow `.github/workflows/pages.yml` запускается вручную: локальные изменения, коммиты и отправка в GitHub сами по себе не обновляют сайт.
В настройках репозитория **Settings → Pages → Source** нужно выбрать **GitHub Actions**. Для публикации открыть **Actions → Publish site to GitHub Pages → Run workflow**, выбрав `main`.
На сайт передаются только `index.html` и публичные файлы `assets/`. Git, README, служебные файлы и инструменты разработки не включаются в сайт. Пароли и токены не сохраняются в проекте; стандартный временный `GITHUB_TOKEN` выдаётся самим GitHub Actions.

## Структура

- `index.html` — страница и подключения стилей блоков.
- `assets/css/base.css` — сброс, общие контейнеры, типографика, отступы, доступность и адаптив.
- `assets/css/blocks/` — отдельный CSS каждого блока; классы именуются по блоку.
- `assets/js/` — обычный JavaScript, добавляется по мере появления интерактивности.
- `assets/images/` и `assets/fonts/` — локальные изображения и шрифты.

## Правила разработки

Блоки создаются поочерёдно по референсам. Общие цвета, шрифты и отступы заданы в `base.css`. Единые точки адаптива: планшет до 1024px включительно, телефон до 767px включительно. При ширине 768px отображается планшетная версия. Минимальная ширина — 320px.

Контейнер: 1440/1312px на ПК, 768/696px на планшете, 360/312px на телефоне. Боковые отступы: 64/36/24px. Шрифты Overpass и Nunito Sans подключены через Google Fonts; для их загрузки нужен интернет.

Шапка: отдельные стили `assets/css/blocks/header.css`, поведение `assets/js/header.js`. При прокрутке больше 200px шапка закрепляется; её место сохраняется, чтобы контент не прыгал. На телефоне кнопка «Меню» открывает остальные пункты и закрывается по Escape, клику вне шапки или выбору ссылки.

Ссылки навигации подготовлены под будущие блоки (`catalog`, `top-positions`, `reviews`, `documents`, `contacts`). Адреса мессенджеров пока не заданы, поэтому иконки не имеют внешних переходов. Кнопка «Обратный звонок» временно ссылается на телефон до добавления формы заявки.

Каждое завершённое изменение сохраняется отдельным Git-коммитом. Перед правками проверяется состояние репозитория, чужие изменения сохраняются.

HTML использует смысловые элементы, доступные подписи и правильную иерархию заголовков. Финальные title, description, canonical, Open Graph, robots.txt, sitemap.xml и структурированные данные добавляются по реальному содержимому и адресу сайта перед публикацией.

## Локальный просмотр

Адрес: http://127.0.0.1:8000

Если установлен Python: `python -m http.server 8000 --bind 127.0.0.1` из папки проекта.

Если установлен PHP: `php -S 127.0.0.1:8000` из папки проекта. Для проверки PHP-обработчиков нужен именно PHP-сервер.

Главный экран: `assets/css/blocks/hero.css` и `assets/js/hero.js`. Четыре слайда: погрузчик, штабелер, рохля, ричтрак; каждый объект в массиве `slides` хранит показатели справа и фото; левый блок не меняется. Автопереключение — 10 секунд, прогресс на правой линии сбрасывается при переключении. При фокусе внутри слайдера и в скрытой вкладке автопереключение приостанавливается. При уменьшении анимации в настройках устройства плавные эффекты отключаются.

Фото и фон первого экрана загружаются с `fetchpriority="high"`, `loading="eager"` и preload. Фото остальных слайдов запрашиваются после события `load` в свободное время браузера; повторяющиеся адреса используют один запрос и кэш. Для будущих изображений вне первого экрана используется `loading="lazy"` с заданными шириной и высотой. Кнопка главного экрана «Подобрать оборудование» ведёт к форме `equipment-selection`.


Форма подбора: `assets/css/blocks/equipment-form.css` и `assets/js/equipment-form.js`. Списки включаются последовательно: категория → грузоподъемность → бренд. Смена предыдущего списка сбрасывает последующие. Выбранная категория подсвечивает соответствующую SVG-иконку. Кнопки пока не выполняют действий. Мобильная компоновка следует референсу: поля и кнопки в колонку.


Секции оборудования и услуг используют общие отступы из base.css: 120px на ПК, 64px на планшете и телефоне. Сетка оборудования: 4 / 4 / 2 колонки; услуг: 5 / 5 / 2 колонки, последняя карточка на телефоне занимает всю строку. SVG-фигуры оборудования меняют цвет, иконки услуг переключаются на акцентную версию при наведении и фокусе с клавиатуры. Фотографии загружаются отложенно.


Популярная техника: отдельные popular.css и popular.js, табы с клавиатурной навигацией, циклическое листание по одному товару и 4 / 2 / 1 видимых карточки. Фотографии скрытых карточек получают src при первом показе. Пока заполнена только первая категория четырьмя карточками из макета; остальные отображают пустое состояние. Кнопки заявки пока без обработчика. Карточки оборудования и услуг предназначены для будущих ссылок; URL страниц ещё не заданы.


Форма заявки: отдельные application.css/application.js, обязательные имя, телефон и согласие; один файл с отображением имени и удалением; локальная проверка полей. Серверная отправка не подключена. Ссылки на согласие и политику ведут на отдельные страницы с черновиками документов. Кнопки товаров прокручивают страницу к форме. Обрезка текста всех кнопок cap height to baseline задана в base.css.


Отзывы: reviews.css/reviews.js, по одному отзыву, ручное циклическое листание стрелками и клавишами влево/вправо. Один предоставленный отзыв и три временные копии для проверки переключения. Заголовок и навигация слева на ПК, сверху на планшете; на телефоне фото и текст расположены столбцом, стрелки внизу.


Документы: documents.css/documents.js, циклический слайдер 4 / 3 / 1 документа на ПК / планшете / телефоне. Скрытые изображения подключаются при первом показе. Сертификаты открываются в отдельной вкладке; кнопка запроса ведёт к форме заявки.


Видео и бренды: общий контейнер media-showcase.css, стили отдельных блоков videos.css и brands.css; листание в media-showcase.js. На ПК блоки рядом, на планшете и телефоне друг под другом. Видео 2 / 2 / 1 карточки; сетка шести брендов 3 / 3 / 2 колонки. Пустые ссылки «Смотреть все» не выполняют переход. Логотипы предоставлены, файлы видео пока отсутствуют — карточки временные.

Форма консультации: consultation.css, три колонки на ПК, две на планшете, одна на телефоне. Использует общие поля и проверку обязательных данных из application.css/application.js. Отправка пока не подключена. Предоставленное изображение погрузчика спереди consultation-forklift.png видно на ПК и телефоне; на планшете скрыто по макету. На телефоне фото расположено перед заголовком.

О компании: about.css/about.js, текст из макета и раскрывающиеся дополнительные абзацы. Подвал: footer.css, бренд, навигация из двух колонок (6/5 пунктов), каталог и контакты на ПК и планшете, вертикальная компоновка групп на телефоне; контакты, внутренние якоря и временные ссылки каталога. Секции сохраняют общие интервалы 120/64px.

## Внутренние страницы

На главной «Читать больше...» раскрывает три дополнительных абзаца и меняется на «Скрыть текст». Поведение — about.js, доступное состояние aria-expanded и управление с клавиатуры.

Подготовлены about.html, careers.html, vacancy-sales.html, buyout.html, promotions.html, service.html, payment.html, delivery.html, reviews.html и contacts.html по ТЗ из Word. Все доступны через ссылки в подвале. Внутренние страницы используют общие стили главной, шапку, подвал и хлебные крошки; дополнительные компоновки — inner-pages.css. Новые фотографии отсутствуют: вместо них оставлены пустые белые или тёмные области. Готовые категории, услуги, логотипы и общие SVG переиспользованы с главной.

Контент страниц и повторяющиеся блоки собраны в scripts/build-pages.py. После изменения общей шапки/подвала или содержимого этого файла запустите `python scripts/build-pages.py` из корня проекта. Получаются обычные статические HTML, пригодные для GitHub Pages без серверной сборки. Ручной процесс публикации подготовлен для всех корневых HTML; автоматически сайт не публикуется.

Отзывы фильтруются табами с управлением стрелками, Home и End; текстовые отзывы — временные копии предоставленного примера, видео — пустые карточки. Акции демонстрируют активное и завершённое состояния, без выдуманных сроков и скидок. Отдельная карточка вакансии заполнена только для менеджера по продажам из ТЗ; две остальные вакансии ведут к общей форме отклика. FAQ выкупа содержит предварительные ответы, которые нужно подтвердить перед публикацией.

Формы резюме поддерживают один файл, формы выкупа — несколько фотографий с выводом имён. Кнопки связи на странице контактов открывают модальное окно с темой обращения, обязательными именем и телефоном; Escape закрывает окно и возвращает фокус кнопке. Яндекс Карты подключены по предоставленному адресу поисковым запросом; точную метку офиса можно заменить ссылкой из конструктора после уточнения. Отправка всех форм по-прежнему не подключена, юридические документы подготовлены как черновики с полями для реквизитов и фактических процессов; адреса мессенджеров ожидаются.

Проверены все десять страниц на ширинах 1440, 768 и 360px: без горизонтальной прокрутки и сломанных изображений; локальные файлы, якоря, уникальные ID и по одному H1. Проверены раскрытие текста, табы отзывов, обязательные поля и закрытие диалога, выбор/удаление резюме и прикрепление нескольких фото.


Обновление компоновки: первый экран страницы компании ограничен шириной контента и имеет радиус 6px; заголовок «Компания в движении» убран. Карточки открытых вакансий имеют пропорцию 2:1 вместо квадрата. Страница вакансии: две равные колонки, слева закреплённый блок под шапкой, справа четыре раздела с промежутком 32px; условия оформлены списком. Кнопка отклика использует hero__cta с главной. На телефоне колонки идут друг под другом, закрепление отключено.

Cookie: общий блок cookie.css/cookie.js на всех 13 страницах. Белое окно по ширине контента, нижний отступ 24/16px, кнопка Принять. Выбор сохраняется локально под ключом pogruzchik-cookie-accepted-v1, очистка данных сайта возвращает уведомление. Оно не запускает аналитику и не заменяет согласие в форме. Страницы personal-data-consent.html и privacy-policy.html генерируются из scripts/legal_content.py; черновики требуют заполнения реквизитов, сроков хранения и используемых сервисов. Мобильные этапы выкупа идут по два в ряд.
